# linodl React 桌面界面重构设计

**日期：** 2026-07-29  
**状态：** 待用户评审  
**目标：** 将现有 CustomTkinter 界面替换为 React 桌面界面，在保留 Python 业务逻辑的前提下提升视觉品质，并保证普通窗口和最大化窗口均能稳定排版。

## 1. 背景

当前 Python 核心业务已经能够完成搜索、目录读取、下载、校验、导出和 CloakBrowser 人工验证。现有 CustomTkinter 界面存在两个主要问题：

1. 视觉层级和品牌识别度不足，整体接近通用后台面板。
2. 布局依赖固定尺寸和按比例拉伸，最大化后输入框、空状态和滚动区域被无限放大，产生大面积无效空白。

本次重构只替换桌面呈现层和交互编排层，不重写下载器、目录解析、校验、导出或浏览器实现。

## 2. 技术方案

采用 **React + TypeScript + Vite + pywebview**。

- React 负责页面、组件、状态呈现和响应式布局。
- Vite 负责前端开发和静态资源构建。
- pywebview 创建独立 Windows 桌面窗口，并将构建后的前端资源作为本地页面加载。
- Python 桥接层向前端暴露受控命令，调用现有业务服务和 Worker。
- Python 通过事件总线向前端推送任务进度、验证状态和结果快照。
- 旧 CustomTkinter 界面暂时保留为兼容入口，React 界面成为默认入口；新界面稳定后再决定是否删除旧界面。

不采用 Tauri。它会引入 Rust、Sidecar 生命周期和额外进程通信，当前收益不足以抵消迁移成本。

## 3. 架构边界

### 3.1 前端

前端只负责：

- 显示页面和组件。
- 收集用户输入。
- 调用桥接命令。
- 消费任务快照和事件。
- 保存纯展示偏好，例如侧栏折叠状态。

前端不直接：

- 访问小说站点。
- 启动 CloakBrowser。
- 读写下载文件。
- 持有代理凭据。
- 判断下载、验证或导出是否成功。

### 3.2 Python 桥接层

新增独立的桌面 API 层，职责包括：

- 校验前端传入的数据。
- 调用已有 Worker 或业务服务。
- 将 Python 模型转换为可序列化 DTO。
- 返回稳定的成功或错误结构。
- 对错误消息执行现有的敏感信息脱敏。
- 管理前端订阅和窗口关闭时的任务清理。

桥接层不包含页面布局逻辑，也不复制下载业务。

### 3.3 现有业务层

以下模块继续作为唯一业务实现：

- `linodl/core/`
- `linodl/config/`
- `linodl/models/`
- `linodl/gui/tasks.py` 中可复用的任务状态模型
- `linodl/gui/workers.py` 中与 Tk 控件无关的 Worker
- `linodl/gui/verification.py`

若现有 Worker 直接依赖 Tk 面板对象，则只抽取事件适配器，不修改其业务结果。

## 4. 页面结构

默认界面由五个一级页面组成：

1. **阅读工作台**：搜索、粘贴目录 URL、查看作品、选择分卷并开始下载。
2. **内容校验**：选择本地书籍，运行结构检查并展示可执行的修复建议。
3. **阅读档案**：浏览已下载作品、导出 EPUB、打开输出目录。
4. **浏览档案**：显示 CloakBrowser 档案健康状态，启动检查或人工验证。
5. **设置**：下载目录、代理、GeoIP、主题及其它兼容配置。

任务检查器属于应用级区域，不是独立页面。切换页面不会丢失任务进度。

## 5. 视觉系统

产品定位为“轻小说资料工作室”，视觉语言来自书脊、书签、卷册和资料卡，而不是通用后台仪表盘。

### 5.1 色彩角色

- **墨蓝**：导航、品牌锚点和主要结构。
- **雾白**：主工作面，不使用纯白大面积铺底。
- **群青**：主要操作、当前步骤和选中状态。
- **琥珀**：需要用户注意但不属于错误的状态。
- **松石绿**：浏览档案健康、完成和可继续状态。
- **胭脂红**：失败、取消和危险操作。

颜色在前端集中定义为设计令牌，组件不得直接散落十六进制颜色。

### 5.2 字体角色

- 中文正文和控件使用清晰的无衬线字体。
- 作品标题使用同字体的中等字重和更紧凑的字距。
- 英文眉题、任务编号和技术信息使用等宽字体。
- 字体文件随前端资源一起分发，离线运行不依赖在线字体服务。

### 5.3 标志性元素

“章节进度书签”是唯一强调性装饰：它把查找、选卷、下载和入档连成连续轨迹，同时承担实际流程状态表达。

其它区域保持克制，不使用无意义渐变、统计卡片或装饰性图表。

## 6. 响应式布局

界面使用 CSS Grid 和容器宽度判断，不根据屏幕分辨率硬编码组件尺寸。

### 6.1 宽屏模式

适用内容宽度不小于 1400 px：

- 展开书脊导航。
- 顶部命令区保持单行搜索。
- 主工作区采用“主舞台 + 固定范围任务检查器”。
- 主舞台最小宽度为 720 px。
- 任务检查器宽度限制在 320–420 px。
- 整体内容设置最大有效宽度并居中，额外空间作为呼吸区，不拉伸表单和列表。

### 6.2 标准桌面模式

适用内容宽度 980–1399 px：

- 导航缩为图标栏，可通过按钮展开。
- 顶部标题与搜索分为两行。
- 主舞台保持单列。
- 任务检查器移动到主舞台下方，并以双列显示任务与最近档案。

### 6.3 紧凑模式

适用内容宽度小于 980 px：

- 维持最小可用窗口宽度，不承诺移动设备使用。
- 导航仅显示图标和提示。
- 所有工作区改为单列。
- 步骤书签简化为四个节点，不显示连接说明。
- 次要元数据隐藏或折叠，但主要操作始终可见。

### 6.4 高度处理

- 页面头部、命令区和流程书签只占内容所需高度。
- 只有结果列表和任务日志允许内部滚动。
- 空状态不得设置为填满剩余高度。
- 最大化时增加可见列表行数，不增加空状态高度。

## 7. 核心组件

### 7.1 `DesktopShell`

负责窗口级布局、导航、页面路由、主题和全局任务检查器。

### 7.2 `CommandDeck`

提供统一的作品名或目录 URL 输入。提交后由桥接层判断业务类型，前端只显示解析结果。

### 7.3 `ChapterRibbon`

根据任务和页面状态显示查找、选卷、下载和入档进度。节点状态仅包含未开始、当前、完成、等待用户和失败。

### 7.4 `WorkbenchStage`

根据状态显示：

- 引导空状态。
- 搜索结果。
- 作品摘要和分卷列表。
- 下载结果和下一步操作。

这些状态互斥，避免把多个大面板同时堆叠。

### 7.5 `TaskInspector`

显示运行中、等待用户和最近完成的任务。支持取消、恢复输入、查看技术详情和跳转到人工验证。

### 7.6 `BrowserProfileStatus`

显示真实检测结果，提供检查档案和打开人工验证操作。不会把未知状态显示为健康。

## 8. 数据流

1. 用户在 React 页面触发操作。
2. 前端调用 `window.pywebview.api.<command>()`。
3. Python API 校验参数并创建任务。
4. 现有 Worker 执行业务操作，将事件写入统一任务存储。
5. 前端定时拉取轻量任务快照；需要用户操作或任务完成时，Python 可主动发出窗口事件。
6. React Store 合并快照，更新页面和任务检查器。
7. 页面卸载不会取消任务；只有显式取消、程序退出或业务失败会改变任务生命周期。

第一阶段使用低频快照轮询，避免立即引入复杂双向通信。轮询接口只返回版本号变化后的数据，减少无效渲染。

## 9. 错误处理

桥接命令统一返回：

```json
{
  "ok": false,
  "error": {
    "code": "PROFILE_BUSY",
    "message": "浏览档案正在被另一个任务使用。",
    "action": "等待当前任务结束，或取消当前任务后重试。"
  }
}
```

- `message` 面向用户，说明发生了什么。
- `action` 给出下一步。
- 技术堆栈只进入可展开的详情。
- 所有 URL、代理、Cookie 和配置错误在进入前端前脱敏。
- 前端未知异常使用统一错误边界，保留导航和任务检查器，不显示空白窗口。

## 10. 桌面窗口行为

- 默认窗口大小为 1280 × 820。
- 最小窗口大小为 900 × 640。
- 记住上次正常窗口尺寸、位置和最大化状态。
- 关闭窗口时若有运行任务，提示用户选择继续后台等待或确认退出。
- pywebview 生产模式加载本地构建资源，不启动外部浏览器。
- 开发模式允许连接 Vite 开发服务器，但不作为正式启动方式。

## 11. 兼容与迁移

采用纵向切片迁移：

1. 先建立桌面壳、桥接层和工作台。
2. 接入搜索、目录和下载。
3. 接入任务检查器和人工验证。
4. 迁移校验、档案和设置。
5. 将 React 入口设为默认，CustomTkinter 保留为显式回退参数。

任何阶段都不删除用户下载目录、浏览档案或现有配置。

## 12. 测试与验收

### 12.1 Python

- 桥接命令输入校验测试。
- DTO 序列化测试。
- 任务创建、取消、恢复和人工验证测试。
- 现有完整 pytest 套件继续通过。

### 12.2 前端

- 关键组件单元测试。
- 三个布局断点的组件渲染测试。
- 任务快照合并和错误状态测试。
- 构建检查和 TypeScript 类型检查。

### 12.3 基础桌面验收

- 普通窗口启动并完成页面切换。
- 最大化后没有横向溢出、无限拉伸或大面积空状态。
- 从搜索到分卷选择的基本流程可用。
- 任务在切换页面后继续显示。
- CloakBrowser `about:blank` 冒烟检查继续通过。

## 13. 不在本次范围

- 重写下载、目录解析或 CloakBrowser。
- 自动破解验证码。
- 跨平台安装包。
- 云同步、账号系统或远程服务。
- 删除旧 CustomTkinter 界面。
