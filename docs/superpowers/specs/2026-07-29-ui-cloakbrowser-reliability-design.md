# Linodl 阅读工作台与 CloakBrowser 可靠性设计

日期：2026-07-29
状态：已确认

## 1. 背景

当前桌面端能够完成搜索、下载、校验和导出，但页面彼此割裂、视觉层级较弱，任务状态与浏览器验证状态也不够清晰。项目已正确集成并实际使用 CloakBrowser 的持久化浏览器上下文，不过现有集成还存在验证页误判、无头模式下无法人工验证、同一档案并发占用、GeoIP 配置不完整和 vendored 版本说明不足等问题。

本次改造同时处理 UI 与 CloakBrowser 可靠性，目标是在不改变核心下载能力的前提下，把应用整理成清晰、可恢复、可观察的“阅读工作台”。

## 2. 目标

- 将分散的功能页重构为连续的阅读工作流。
- 明确展示当前步骤、任务进度、最近档案和浏览档案健康状态。
- 只在确实遇到验证页时暂停任务，并打开可见浏览器供用户完成验证。
- 验证完成后恢复原任务和输入，不要求用户重新操作。
- 防止同一个浏览档案被多个任务同时打开。
- 修正 GeoIP、视口和启动参数的使用方式。
- 补齐 CloakBrowser 的许可证、版本和可选依赖说明。

## 3. 非目标

- 不实现验证码自动破解或绕过。
- 不重写下载、解析和导出核心算法。
- 不引入远程账户、云同步或多用户系统。
- 不将在线站点作为自动化测试的硬依赖。
- 本次只做基础验收，不进行完整的多分辨率、明暗主题和长时间稳定性矩阵测试。

## 4. UI 设计

采用已确认的“阅读工作台”方向：

- 左侧导航包含：阅读工作台、内容校验、阅读档案、浏览档案、设置。
- 主区域顶部显示连续步骤：查找作品 → 选择分卷 → 下载内容 → 校验与导出。
- 搜索词和作品 URL 进入同一个入口，由输入内容自动路由。
- 工作台同时展示最近阅读档案和任务中心，减少页面往返。
- 浏览档案状态使用明确的文字与颜色共同表达，不只依赖颜色。
- 视觉基调为深墨蓝、青蓝强调色和书脊式内容标识；保持 CustomTkinter 原生实现，不引入 Web 前端运行时。
- 窗口空间不足时优先保证核心操作与任务状态可见，次要信息允许折叠或滚动。

任务中心展示任务名称、当前阶段、进度、可执行操作和简要错误。错误可展开查看技术详情，但默认只呈现用户可理解的原因与处理建议。

## 5. 浏览器架构

### 5.1 BrowserProfileCoordinator

增加按浏览档案绝对路径管理的协调器。同一档案同一时间只允许一个浏览器上下文持有租约；其他任务进入等待状态，并在 UI 中显示“等待浏览档案”，而不是直接并发启动导致 Chromium 档案锁冲突。

租约必须在成功、失败和取消路径中统一释放。协调器只管理进程内并发，不尝试强制终止外部浏览器进程。

### 5.2 验证页判断

将验证判断改为三态：

- `normal`：页面正常，可继续任务。
- `challenge`：存在强验证特征，需要人工处理。
- `unknown`：页面异常或信息不足，先按普通网络/页面错误处理。

单独出现通用的 `cdn-cgi/challenge-platform` 脚本不能判定为验证页。只有标题、可见验证控件、特征路径、明确验证文案等强特征组合才进入 `challenge`。

### 5.3 VerificationService

默认下载仍可使用无头模式。确认遇到验证页后：

1. 保存原任务类型、输入、分卷选择、输出目录和当前阶段。
2. 释放原浏览器上下文，但保留同一持久化档案。
3. 使用可见 CloakBrowser 重新打开目标页面。
4. 等待用户完成验证或主动取消。
5. 重新检查目标页面，而不是只检查某个特定 Cookie。
6. 验证通过后关闭可见浏览器并恢复原任务。

服务不点击验证码、不注入破解脚本，也不承诺一定生成 `cf_clearance`。

### 5.4 CloakBrowser 参数

- 保留 `launch_persistent_context` 和稳定档案目录。
- 移除自定义 `1920×1080` 视口，使用上游默认指纹组合。
- 启用 GeoIP 时不再强制传入 `zh-CN` locale，避免覆盖上游地理匹配结果。
- 无代理时禁用 GeoIP，并在设置界面给出原因。
- 增加 GeoIP 与 SOCKS 所需可选依赖和友好缺失提示。
- 缩小旧版本兼容分支的 `TypeError` 捕获范围，避免掩盖真实启动错误。

vendored CloakBrowser 保持可审计。升级 Python 包装层到确认兼容的版本；没有合法授权密钥时继续使用公开可用的 Chromium 构建，不自动切换到需要授权的新构建。仓库补充上游 MIT License 和版本来源说明。

## 6. 任务状态与取消

任务至少包含以下状态：

`queued`、`waiting_for_profile`、`running`、`waiting_for_verification`、`cancelling`、`cancelled`、`failed`、`completed`。

取消请求通过每个任务独立的取消事件向下载循环、浏览器等待和验证服务传播。只有后台工作真正退出后才标记为 `cancelled`，避免界面显示已取消但任务仍在运行。

失败和取消都保留任务输入；用户可以修正设置后重试。任何异常都不得自动删除浏览档案、输出目录或已下载文件。

## 7. 数据流

```text
用户操作
  → TaskManager 创建任务并保存输入快照
  → BrowserProfileCoordinator 获取档案租约
  → BrowserSession 打开目标页
  → ChallengeAssessment
      ├─ normal：继续搜索/下载
      ├─ challenge：VerificationService 可见验证 → 复检 → 恢复任务
      └─ unknown：按页面或网络错误报告
  → 释放档案租约
  → 更新任务中心与最近档案
```

UI 只通过任务事件更新，不直接操作后台浏览器对象。所有 Tk 控件更新回到主线程执行。

## 8. 错误处理

- 用户信息包含：发生了什么、是否保留了输入、下一步能做什么。
- 技术详情包含异常类型、阶段和必要日志，但不显示代理密码、密钥等敏感值。
- 浏览器启动失败时区分依赖缺失、二进制缺失、档案占用和一般启动异常。
- 验证超时后任务停留在可重试状态，不误报下载失败。
- UI 初始化失败不得破坏配置文件；批量设置尽可能一次写入，避免半更新状态。

## 9. 测试与基础验收

自动测试重点覆盖：

- 普通首页含通用 Cloudflare 脚本时不会被误判。
- 强验证特征能够触发人工验证流程。
- 同一浏览档案的互斥、等待和释放。
- GeoIP、locale、代理和视口参数组合。
- 任务状态迁移、真实取消和输入恢复。
- UI 辅助函数与任务事件路由。

基础验收仅包含：

1. `python -m pytest -q`
2. `python -m compileall -q linodl tests`
3. 启动一次主窗口，确认工作台可打开，核心导航、输入入口和任务区域可见。
4. 运行一次隔离的 CloakBrowser `about:blank` 冒烟检查，确认上下文能够创建并关闭。

在线目标站不作为本次交付的必过验收项；多尺寸、明暗主题和真实验证码流程只做实现层面的合理兼容，不纳入完整手工验收矩阵。

## 10. 迁移与兼容

- 保留现有配置字段，新增字段提供安全默认值。
- 旧下载目录、浏览档案和任务输入继续可用。
- 原功能面板可先作为工作台内部组件复用，避免一次性重写业务逻辑。
- `.superpowers/` 视觉设计临时产物加入忽略规则，不进入产品发布物。
